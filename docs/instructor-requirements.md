# 과제와 연결한 팀 수행 내용

## 실시간 로그 통합 파이프라인

수어 인식·교육 앱에서 발생하는 학습 기록을 Kafka로 수집하고, Spark가 소비해 MongoDB 원장과 학습 통계로 저장하는 파이프라인을 구성했습니다. 교육 화면과 다섯 목표 단어를 중심으로 실제 모바일 전송부터 AWS 저장까지 연결했습니다.

기준일은 2026-11-25입니다. 앱 코드를 검토한 내용, 서버 담당자의 구현 보고, DB 담당자의 실제 조회·시험 결과를 근거별로 표시합니다.

## 강사 과제와 팀 구현의 연결

| 과제 영역 | 팀이 진행한 내용 | 결과·근거 |
|---|---|---|
| Kafka 실시간 로그 수집 | HTTPS 배치 API가 이벤트를 검증하고 Kafka 발행 후 202 응답 | 앱·서버 보고, 실제 Kafka 이벤트 확인 |
| 토픽·파티션을 이용한 추적 | 학습 이벤트 토픽과 user_id 키 사용, 파티션·오프셋 조회 | 이벤트 ID별 발행 위치 대조 |
| Spark 스트리밍 처리 | 상시 Kafka 소비와 학습 통계 계산 | 서버 담당자의 상시 작업·집계 구현 보고 |
| 체크포인트와 재처리 | 소비 위치 관리, 특정 오프셋의 누락 이벤트 배치 재처리 | 누락 4건 복구 후 기존 기록 포함 28건 대조 보고 |
| 재전송 데이터 관리 | 앱의 event_id 유지, MongoDB _id 고유 키 사용 | 실제 원장 구조와 임시 컬렉션 멱등 쓰기 시험 |
| 저장 조회 최적화 | topic·offset 복합 인덱스 적용 | 검사 문서 73→10, 반환 BSON·순서 일치 |

## 2팀 학습 기능과 수집 이벤트

| 사용자 행동 | 이벤트 | 활용 |
|---|---|---|
| 학습 시작 | lesson_started | 학습 단위·목표 단어 추적 |
| 단어 연습 | practice_attempt | 단어별 연습 횟수 |
| 인식 결과 확인 | recognition_result | 성공·오인식·미인식 결과 구분 |
| 재시도 | retry | 이전 결과와 재시도 연결 |
| 학습 완료·종료 | lesson_completed, lesson_ended | 시도·성공 수와 종료 흐름 |
| 번역 결과 확인·수정 | answer_selected | 사용자 확인 일치율 |

## 서버 보고의 학습 지표

| 지표 | 원천 기록 | 의미 |
|---|---|---|
| 1분 단어별 연습 횟수 | practice_attempt | 단어별 연습 활동량 |
| 최근 5분 미인식 비율 | recognition_result | 인식 결과 중 미인식 결과의 비중 |
| 사용자 확인 일치율 | answer_selected | 사용자가 확인한 번역 결과의 일치 여부 |

지표 구현은 서버 담당자의 제공 보고에 근거합니다. 앱 규격의 분모와 식별자는 [데이터 계약](data-contract.md)에 정리했습니다.

## 실제 연동 결과

- 두 아이폰의 서로 다른 user_id·session_id로 발생한 이벤트 총 17건의 MongoDB 저장을 확인했습니다.
- Android 이벤트 7건에서 device·app_version과 Kafka 오프셋을 대조했습니다.
- 실제 앱 이벤트의 event_id·Kafka 위치·원문을 AWS MongoDB와 대조했습니다.
- 조회 인덱스 적용 전후 반환 문서의 전체 BSON 해시와 순서가 일치했습니다.
