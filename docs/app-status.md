# 앱 담당자 확인 결과와 앱 묶음 정리

앱 담당자가 11월 25일에 앱 코드와 실제 폰에서 직접 확인한 내용입니다. 다른 문서에서 "제공 코드 기준"으로 적은 항목의 현재 상태와, 문서 작성에 쓰인 앱 묶음(ZIP)을 정리한 내용을 기록합니다. 서버 주소·접속 키·사용자 ID·이벤트 원문은 적지 않았습니다.

## 앱 묶음 정리

| 대상 | 발견한 것 | 처리 |
|---|---|---|
| `수어칠판_안드로이드앱.zip`의 `expo-board/web/dist/local-key.pem` | PC에서 웹 화면을 폰 카메라로 시험할 때 만든 자체 서명 인증서의 개인키 | 11월 25일 묶음에서 제거 |
| 같은 위치의 `local-cert.pem` | 위 개인키와 짝인 자체 서명 인증서 | 11월 25일 묶음에서 제거 |
| `수어칠판_아이폰앱.zip`의 `Server.plist` | 서버 접속 키가 들어가는 설정 파일 | 묶을 때부터 키를 비워 둠 |
| 안드로이드 묶음의 `server.config.json` | 서버 주소와 접속 키 | 묶을 때부터 제외, 예시 파일만 포함 |

두 `.pem` 파일은 개발용 PC의 로컬 HTTPS 시험에만 쓰던 것입니다. 팀 서버의 인증서·접속 키와 관계가 없고, 설치 파일(APK)에도 들어가지 않습니다(APK 안의 `.pem` 파일 0개 확인). 그래도 개인키이므로 묶음에서 뺐습니다.

이 정리로 안드로이드 묶음의 해시가 바뀌었습니다. [source-materials.json](../evidence/source-materials.json)의 값은 문서 작성 당시 받은 묶음의 것이고, 정리한 뒤의 값은 같은 파일의 `revised` 항목에 적었습니다.

키가 든 설정 파일(`Server.plist`, `server.config.json`), 인증서, 모델, 설치 파일은 앱 소스 폴더의 Git 제외 목록에 넣었습니다. 앱 소스는 아직 Git 저장소에 올리지 않았습니다.

## 앱의 현재 상태

| 항목 | 확인한 내용 | 확인 방법 |
|---|---|---|
| 서버 주소 반영 | 탄력적 IP 주소를 넣은 빌드를 아이폰 한 대에 설치 | 11월 25일 실제 폰 설치 |
| 재전송 | 옛 주소 빌드에서 폰에 쌓여 있던 기록 9건(순번 164~172)이 새 빌드 설치 직후 09:13에 전송되어 모두 HTTP 202 | 폰의 전송 기록 파일 조회 |
| 이후 전송 | 같은 폰에서 "감사" 학습 기록 8건(순번 173~180)이 09:14에 전송되어 모두 HTTP 202 | 폰의 전송 기록 파일 조회 |
| 확신 표시 기준 | iOS `Reading.sureAt = 0.6`, Android `SURE_AT = 0.6`. 두 앱이 같은 값을 씀 | 코드 확인 |
| 손 미검출 기준 | Android `MISSING_WARN = 0.5` | 코드 확인 |
| 실시간 사람 모형 | 11월 24일에 두 앱에서 제거. 학습 화면의 본보기는 그대로 유지 | 코드 확인 |
| 좌표 샘플 | iOS는 폰에 쌓아 두고 서버의 샘플 주소가 열리면 보냄. Android는 최근 12건만 폰에 보관하고 업로드는 미구현 | 코드 확인 |

위 17건은 [검증 결과](verification.md)에 적힌 "11월 25일 기록 9건 09:13:01 수신, 이후 8건 추가 저장"과 같은 기록입니다. 폰이 받은 202 응답과 DB 원장 조회가 서로 맞습니다.

안드로이드 폰과 다른 아이폰 한 대에는 옛 주소 빌드가 남아 있어, 새 빌드를 설치하기 전까지 기록이 폰에 쌓입니다. 확신 표시 기준 0.6은 표시용 임시 기준이며 정확도가 아닙니다. 독립 평가셋으로 정한 값이 아닙니다.

## 동의와 수집 범위

두 앱 모두 처음 켰을 때 한 번 동의 화면을 띄우고, 동의해야 앱을 쓸 수 있습니다. 동의 전에는 기록을 만들지 않습니다.

| 구분 | 내용 |
|---|---|
| 보내는 것 | 연습한 낱말, 앱이 읽은 결과, 수어 동작의 좌표(손과 몸의 점) |
| 식별 | 이름 없이 앱이 만든 임의의 번호 |
| 보내지 않는 것 | 카메라 영상, 사진, 이름. 영상은 폰에도 저장하지 않음 |
| 용도 | 앱이 수어를 더 잘 읽도록 다시 학습시키는 데 사용 |

초기 설계의 "선택적 동의"는 11월 23일 팀 결정으로 "동의 후 항상 수집"으로 바뀌었습니다. 수집한 기록의 삭제 요청 절차는 아직 정하지 않았습니다.

## 기기 값의 뜻

| 값 | 뜻 |
|---|---|
| `device=iPhone19,7` | 아이폰의 기종 식별자. iPhone 18 Pro Max |
| `device=android-16` | 안드로이드 운영체제 주 버전(Android 16). 제조사·기종은 담기지 않음 |
| `app_version=1.0` | iOS 앱 |
| `app_version=1.0-expo` | Android 앱. 브라우저에서 연 웹 화면은 `1.0-web`이고 device 앞에 `web-`이 붙음 |

안드로이드 기록만으로는 제조사와 기종을 알 수 없습니다. 필요하면 별도 필드를 규격에 추가해야 합니다.

## 앱 보안 점검

11월 25일에 흔한 공격 항목을 앱에 대조해 점검했습니다. 결제·가입·로그인·파일 올리기·AI 대화 기능은 없어 해당 항목은 제외했습니다.

| 항목 | 상태 | 조치 |
|---|---|---|
| 앱 안의 접속 키 | 설치 파일을 뜯으면 꺼낼 수 있음 | 앱에서 막을 수 없음. 서버의 요청 횟수 제한·키 교체 절차 필요 |
| 사용자 번호 변조 | 키를 가진 쪽은 다른 번호로 기록을 보낼 수 있음 | 재학습에 쓰기 전에 걸러야 함 |
| 안드로이드 화면 이동 | WebView가 임의 주소로 이동할 수 있었음 | 앱 안의 페이지만 열리게 제한 |
| 기록 전송 중계 | 페이지가 넘긴 글에 그대로 키를 붙여 보냄 | 기록 묶음 형식과 크기를 검사한 뒤 보냄 |
| 안드로이드 백업 | 앱 저장 내용이 기기 백업에 포함됨 | 백업 제외 |
| 서버 주소 바꾸기 인자 | 실행 인자로 주소·키를 바꿀 수 있음 | 개발용 빌드에서만 허용 |
| 서버의 관리·문서 주소 | 관리·문서·설정 파일 주소 11개가 모두 404 | 조치 불필요 |

안드로이드 변경은 빌드와 엔진 시험까지 확인했고, 실제 폰 설치 후 동작은 확인하지 않았습니다. 가짜 기록은 서버에 넣지 않았으므로, 서버·DB의 입력 처리(쿼리 주입 등)는 이 점검의 범위가 아닙니다.
