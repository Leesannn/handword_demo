# 팀 발표 진행안

주제는 ‘수어 학습 앱을 위한 실시간 로그 통합 파이프라인’입니다. 앱 기능, 수집·처리 구조, DB 연결·조회 개선과 실제 검증 순서로 설명합니다.

## 12분 기술 발표 흐름

| 순서 | 시간 | 자료 | 설명 |
|---|---|---|---|
| 1 | 1분 | 프로젝트·학습 화면 | 제한된 어휘의 수어 교육과 학습 로그 통합 |
| 2 | 1분 | MediaPipe 전개도 | 원시 검출·손 배정·마스크·정규화·30프레임 |
| 3 | 1분 | 입력 계약·평가 표 | XYZ와 XY+마스크 구분, 124개 분할·kNN 기준선 |

## 역할별 설명 포인트

### 앱·추론 담당

MediaPipe 좌표를 공통 입력 규격으로 전처리한 뒤 iOS Core ML·Android JavaScript GRU로 판정합니다. 학습 행동과 인식 결과를 이벤트로 만들고 Outbox에 보관해 전송합니다. 제공 단일 기준 입력의 전처리·확률 재계산 결과를 함께 설명합니다.

### 메인 서버 담당

Caddy HTTPS와 FastAPI 인증·입력 검증을 거쳐 이벤트를 Kafka에 발행합니다. Spark 상시 소비·학습 지표·체크포인트 운영과 특정 오프셋 재처리를 설명합니다. 이 항목의 자료 근거는 서버 담당자의 제공 보고입니다.

### DB·연결 담당

별도 계정의 MongoDB를 PrivateLink·TLS로 연결하고, 앱 이벤트 ID·Kafka 위치·원문을 대조했습니다. 최근 기록의 전체 스캔을 복합 인덱스로 개선한 실행 계획과 임시 컬렉션의 예외 시험을 보여줍니다.

## 실제 연동을 보여주는 순서

1. 실행 중인 앱·API·Kafka·Spark·MongoDB를 확인합니다.
2. Kafka와 DB의 현재 처리 위치를 기록합니다.
3. 두 폰에서 연습하고 event_id·HTTP 응답을 확보합니다.
4. Kafka에서 해당 ID의 파티션·오프셋을 확인합니다.
5. MongoDB에서 같은 ID·사용자·세션·원문을 대조합니다.
6. 인덱스 전후 실행 계획과 기존 검증 결과를 설명합니다.

앱 키·DB 비밀번호·개인키는 화면에서 가립니다. 재전송은 전체 건수 증가 대신 해당 이벤트 ID와 원문으로 확인합니다.

## 예상 기술 질문

| 질문 | 답변 요점 |
|---|---|
| test 96.875%는 앱 정확도인가요? | 8개 임시 클래스·32건 고정 시험의 MediaPipe kNN 결과입니다. 앱 r0006 GRU의 수치와 구분합니다. |
| 같은 177값이면 바로 모델에 넣나요? | 실험 XY+마스크와 모바일 XYZ는 의미·슬롯·전처리가 다른 입력 계약입니다. |
| 중복 집계는 어떻게 시험했나요? | 영상 완료 이벤트를 3회 재전달해 원장·누적·1분 창·원장 시각을 대조한 기록을 제시합니다. |
| 서버에서 수어를 추론하나요? | 기기에서 추론하고 서버는 학습 로그를 수집·처리합니다. |
| 177과 30은 무엇인가요? | 59개 점의 XYZ 값과 고정 길이 입력 프레임 수입니다. |
| 0.6이면 정확도 60%인가요? | 제공 코드의 확신 표시 기준이며 실측 정확도와 다른 값입니다. |
| 202면 DB 저장도 끝났나요? | Kafka 발행 확인 뒤 수락한 것이며 DB 저장은 비동기입니다. |
| 왜 두 식별자가 필요한가요? | user_id는 사용자 이벤트 배치, event_id는 개별 기록 추적에 사용합니다. |
| 같은 이벤트 재전송은 어떻게 다뤘나요? | 앱이 event_id를 유지하고 원장은 그 값을 _id로 사용합니다. 임시 컬렉션에서 반복 쓰기 한 건 유지를 시험했습니다. |
| 체크포인트와 재처리는 어떻게 사용했나요? | 소비 위치를 관리하고 누락 오프셋 4건을 별도 Spark 배치로 복구했습니다. |
| 원장이 무엇인가요? | 개별 이벤트 원문과 처리 위치를 보관하는 기준 기록입니다. |
| 인덱스 효과는 무엇인가요? | 73건 중 10건 조회의 검사 문서 73→10, 별도 정렬 제거, 원문·순서 일치입니다. |
| 폰 두 대는 어떻게 구분했나요? | user_id·session_id·device를 대조했습니다. |
| 서버 간 SSH 터널이 필요한가요? | 서버 간 DB 적재는 PrivateLink를 사용하고 노트북 SSH는 관리 경로입니다. |
