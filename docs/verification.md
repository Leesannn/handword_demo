대상은 `learning_attempt_test_app_events`이고, 당시 전체 문서는 73건이었습니다. 오프셋 상한을 509로 고정해 최근 10건 조회와 증가분 범위 조회를 각각 실행했습니다.

실행 계획은 `COLLSCAN + SORT`에서 `IXSCAN + FETCH + LIMIT`으로 바뀌었습니다. 반환한 전체 BSON 문서의 SHA-256 해시 목록과 순서를 비교했고 두 조회 모두 일치했습니다. 인덱스 적용 완료 시각은 11월 23일 16:20입니다.

문서 검사량 감소율은 `(73-10)/73 ≈ 86.3%`입니다. 데이터가 작고 시간 해상도가 제한돼 응답 속도 향상률이나 대규모 성능을 주장하지 않습니다. 적용 전 `_id` 단건 조회는 문서 1건·키 1건으로 이미 효율적이었습니다.

## 임시 컬렉션 예외 시험

| 시험 | 방법 | 실제 결과 |
|---|---|---|
| 첫 삽입 | _id 조건 + upsert + $setOnInsert | 1건 생성 |
| 같은 이벤트 재시도 | 동일 쓰기 반복 | 1건 유지, 수정 0건 |
| 같은 ID·다른 내용 | payload를 바꿔 같은 명령 실행 | 최초 문서 유지 |
| 중복 강제 삽입 | 동일 _id로 insert | 오류 11000 |
| 잘못된 값 | 정수 offset 최소값 0의 임시 validator에 음수 삽입 | 오류 121 |
| 종료 | 임시 컬렉션 제거 | 정리 완료 |

이 시험은 별도 임시 컬렉션에 합성 데이터를 사용한 저장 패턴·제약 동작 확인입니다. $setOnInsert로 기존 문서를 보존하는 동작, 고유 키·시험 validator의 오류 코드를 확인하고 임시 컬렉션을 정리했습니다.
